Part I · The work

1. The project in one page

This repository is a research platform for the National Capital Territory of Delhi. It joins air-quality observations to land cover, vegetation, roads, and industry, and it reports associations. The language the interface is written in is “associated with,” “correlated with,” and “observed near.”

The first working path is: import observations, validate and store them, summarise them, serve them through a FastAPI, and show them on a map and a dashboard, with CSV and GeoJSON export. A second, fuller path reads CPCB and XKDR air-quality files, Dynamic World land-cover rasters, an OpenStreetMap extract, and a ward boundary, and answers a specific question about built-up surroundings and annual AQI.

The software is a modular monolith. One React application talks to one Python API. The API talks to PostgreSQL with PostGIS, and it reads large rasters from disk. There is no separate worker fleet and no user login. Version 1 is a local research tool.

The rule that organises everything

A concentration is attached to a place only when a monitoring station is there. A grid cell, a ward, or a coloured patch between stations stays unmeasured until an explicit method fills it, and that fill is labeled.

2. The question and the study design

The operational question is whether monitors sitting in more built-up surroundings also record worse air, and whether that local pattern is the same thing as the rise or fall of the citywide average. Delhi has been adding built-up land, mostly toward the edges, over the same years in which fuels, emission controls, and the 2020 lockdown moved the city mean. The platform keeps those two comparisons apart.

The city is described in config/cities/delhi.yaml. Coordinates used by the analysis are read from that file and from the data files, so a second city is a new YAML file plus a boundary, not a rewrite of the statistics.

Research questions in the methodology notes are treated as hypotheses.

  • Spatial variation. Station summaries and time series. Citywide hotspot products stay off below eight stations.
  • Land cover, vegetation, roads, industry. Grid metrics, plus neighbourhood descriptions around the stations that actually measured the air.
  • Land-cover change. Class areas between years. WorldCover 2020 (v100) and 2021 (v200) use different algorithms, so the API records whether the classification scheme is comparable.
  • Screening priority. Three numbers kept separate: severity from observed pollution, confidence from how complete the record is, and a weighted screening score. An unobserved cell is left unranked. The score is a screening index.

3. What kind of number you are looking at

API payloads that are not raw observations carry data_kind. Reading that field is the fastest way to know what you are allowed to claim.

data_kindMeaning in this project
observedA station reading or a station geometry taken from the imported record.
quality_controlledA reading that has passed a quality flag. Invalid flags are left out of means such as the hotspot average.
aggregatedA mean, a time rollup, a class area, or a buffer polygon computed from stored features.
satellite_indexNDVI, NDBI, or NDWI from reflectance bands.
classifiedA land-cover class map, such as Dynamic World or WorldCover.
statistical_estimateAn interpolation, a correlation, a z-score hotspot, or the built-up versus AQI comparison. The built-up and annual AQI payload uses this label.
model_predictionA fitted line extended beyond the observed years, used when the built-up projection has enough years.
screening_scoreThe priority index. Severity and confidence stay beside it so a low score is not read as clean air.
How to say it

A station dot is an observation. A colour between stations is an estimate. A SAMPLE row is a software fixture. Those three sentences cover most of the questions a reader will ask of a screenshot.

What the research pages read

The presentation, the built-up comparison, and the local questions read files, not the sample sketches.

  • Air, through 2024. XKDR daily JSON under data/raw/xkdr_daily, one file per pollutant and year. The annual index is computed in this project from those daily means.
  • Air, 2025 and 2026. CPCB’s published hourly AQI, ingested from station workbooks into data/processed/cpcb_aqi. 2026 in the method text ends on 31 October, before the high-AQI winter months.
  • Built-up land. A Dynamic World class GeoTIFF per year, DynamicWorld_label_{year}_delhi.tif. Class 6 is built area. The share is taken inside 1 km of each monitor, and the city total is the built area inside the boundary.

Official CPCB observations are obtained by a person exporting CSV or XLSX from the CCR dashboard. The portal uses a captcha. This project does not scrape it. Optional live access, unused unless credentials are set, is OpenAQ, Copernicus Data Space, and Google Earth Engine.

5. The three running services

docker compose up --build starts three containers. The API image is Python 3.12 with GDAL, GEOS, and PROJ, because rasterio and GeoPandas need them. The setup notes suggest about 8 GB of RAM for that image.

The API waits until Postgres is healthy. Its start command is one shell line: migrate, seed, then serve with reload.

alembic upgrade head python -m app.workers.seed uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

A local run without Docker uses Python 3.12, Node 22, and PostgreSQL 16 with PostGIS, usually on port 5432. Copy .env.example to .env. Defaults are enough to boot. Optional variables are OPENAQ_API_KEY, CDSE_CLIENT_ID, CDSE_CLIENT_SECRET, GEE_SERVICE_ACCOUNT, and GEE_PROJECT. The stack starts when those are empty.

There is no Celery. A longer analysis inserts a row in analysis_runs with status queued, runs the function in the request, and stores completed or failed plus the output metadata. Raster work is the same pattern: a function in the API process, reading a GeoTIFF with rasterio.

7. The database

One Alembic revision, 0001_initial_postgis_schema, creates the PostGIS extension and every table. Primary keys are UUIDs. Geometries are stored in SRID 4326. Time columns are timezone-aware.

The core relationships are: a city has many stations, a station has many observations, a city has many grid cells, a grid cell has environmental metrics and land-cover statistics, and a land-cover statistic points at a land-cover dataset. Analysis runs, model outputs, ingestion batches, the dataset catalog, raster assets, and export jobs sit beside that chain.

GiST indexes sit on the city boundary, station points, grid polygons, and each spatial layer. The environmental-metric row is unique on grid, period, and pollutant, so a recompute updates one cell-period rather than appending a silent duplicate.

9. Measurement: coordinates, grid, buffers, interpolation

app/geospatial/crs.py is the gate. Anything that needs metres asks for the city’s projected SRID, which for Delhi is 32643. Buffer polygons are built in that CRS and can be stored or returned as GeoJSON in longitude and latitude. Area in square kilometres uses the projected geometry.

The grid generator cuts the city boundary into cells of grid_resolution_m, default 1000. Each cell gets a stable grid_code. Environmental metrics hang off the cell for a period. If no station falls in the cell, observation_count stays 0 and the concentration stays null. That null is the honest state. It is not a low reading.

Buffers accept a target of stations, roads, industrial sites, or green spaces, and a list of distances. The default list is the one in the city YAML. The response includes a limitation sentence: station buffers do not create extra samples; road and park completeness follow the extract; a missing industrial polygon is not proof of no industry.

Inverse distance weighting lives in app/geospatial/idw.py. Inputs are easting, northing, and a value. The power is 2. If the target is within 1 metre of a station, the function returns that station’s value. The README allows these fills on unmonitored cells only when the city has at least eight stations, and only with data_kind=statistical_estimate.

Contour and annual surfaces in app/geospatial/contours.py draw the coloured map between monitors. The presentation copy states the range used there: on the order of 32 to 39 stations with enough valid days, depending on the year. Those fills are estimates. The station symbols are the observations.

10. Satellite indices and land cover

The city file names Sentinel-2 L2A as the intended reflectance source, with a 20 percent cloud cap, baseline year 2020 and a recent year of 2024, and three indices.

  • NDVI = (B8 − B4) / (B8 + B4). Near infrared minus red.
  • NDBI = (B11 − B8) / (B11 + B8), after the 20 m SWIR band is resampled to 10 m. This is the built-up index from bands, separate from the Dynamic World class.
  • NDWI = (B3 − B8) / (B3 + B8). Optional water index.

On a real Sentinel-2 composite, scene classification classes 3, 8, 9, and 10 — cloud and shadow — should be masked before a mean index is taken. Without Copernicus or Earth Engine credentials, the seed writes the tiny sample GeoTIFFs instead, and the catalog marks them as sample.

WorldCover at 10 m is the intended default land-cover product for 2020 and 2021. Study classes collapse the product legend toward built-up, tree cover, grassland or sparse vegetation, cropland, bare soil, water, and other. Because v100 and v200 were produced with different algorithms, a drop in one class between those two years can be a method change. The change endpoint sets comparable_classification_scheme so the client can say so.

Dynamic World is the product behind the year-by-year built-up story. For a monitor, the code reads the class raster in a 1 km window and returns the share of class 6. For the city trend, it counts built pixels inside the boundary and converts them to square kilometres. Vegetation in the local questions uses classes 1, 2, and 5 in that same window.

11. Statistics the API will compute

Correlation takes two columns from the grid metric table, by default mean NDVI against mean concentration. It returns Pearson, with a Fisher-z confidence interval, and Spearman. The handler reminds the caller that pollution exists only on cells that contain a monitor, so the sample size is the number of monitored cells, and a single-station association is not a citywide law.

Regression is ordinary least squares through statsmodels. The default predictors are mean NDVI, built-up percentage, and road density. Diagnostics include VIF, RMSE, and MAE. Weather enters only when a weather column is one of the predictors. The response records that there is no holdout split in version 1, because observations share locations and a random row split would leak the same site into both sides.

Hotspots, for the database stations, are z-scores of mean PM2.5. A station is marked when z is at least 1. The method string on the result says this is not an interpolated surface and not Getis-Ord Gi*. If the station count is below hotspot_min_stations, the endpoint returns status refused and still writes the run, so the refusal is auditable. Moran’s I is implemented for a value vector and a spatial-weights matrix, for the case where the station count clears the same threshold the methodology asks for.

Priority scores each grid row with separate severity, confidence, and a weighted screening priority. Default weights can be replaced in the request body. The route returns at most 200 cells, labeled screening_score, with the note that the three components stay separate.

12. The built-up and AQI analysis

This is the analysis the presentation page is built on. The code is app/analytics/builtup_aqi_years.py together with app/analytics/daily_aqi.py. Years are 2018 through 2026. Each year is a cross-section. The citywide AQI trend is reported next to built-up growth and is not attributed to it.

How an annual AQI is made, 2018–2024

The label in code is “CPCB AQI from 24-hour PM2.5, PM10, NO2, SO2, and NH3.” CO and ozone are left out because CPCB indexes them on an 8-hour maximum, which a daily mean does not provide. A daily mean needs 16 or more hours. A station-day needs at least three of those pollutants, and one of them must be PM2.5 or PM10. The daily index is the maximum sub-index, using CPCB breakpoint tables stored in code. A station-year needs 180 or more valid days, then the annual value is the mean of those days.

How 2025 and 2026 differ

Those years use the mean of CPCB’s published hourly AQI, again requiring 16 or more hours in a day. A change in the series that crosses from 2024 into 2025 mixes a definition change with any real change. 2026 stops on 31 October, so November and December are absent, and those are high-AQI months. The payload marks a partial year.

The comparison inside one year

Monitors with a valid annual AQI are paired with their Dynamic World built-up share within 1 km. The year record then contains:

  • Pearson r between built-up share and AQI, and its p-value.
  • An OLS slope, reported as AQI points per 10 percentage points of built-up share, and R².
  • A tercile contrast: the mean AQI of the third of monitors with the most built-up land nearby, minus the mean of the third with the least.

The city trend row for that year is the mean of the station annual values, the station count, the built-up area inside the boundary, and the share of monitor-days at Poor or worse. The map can show the level in one year or the change between two years. Change classes run from −50 to +50 AQI so a colour means the same change on every pair of years. Level classes are also fixed, in steps of 10, so a colour means the same AQI in 2018 and in 2024.

The projection page fits a straight line through Dynamic World built area for every mapped year and draws a 95 percent interval. A city-mean AQI line on year is fit only for the concentration-based index, and only when at least eight such years exist. Hourly-index years stay out of that line. The within-year gap between more built-up and less built-up monitors is not converted into a future city average. When the fit succeeds, that payload is a model_prediction.

13. Neighbourhood questions at the monitors

app/analytics/local_questions.py answers five questions at Delhi monitors. Concentrations stay on the monitor. Roads, industry, and parks are read from the Overpass file. Cells and polygons without a monitor stay unmeasured. The 2024 means used here are hour-weighted months from the XKDR extract: a month needs at least 336 hours, and a station needs at least six such months.

A related land-use page follows the Badia et al. (2025) contrast: monitors with the most of a land cover within 1 km against monitors with the least, reported as a percent difference for pollutants such as PM2.5 and NO2.

15. Configuration, another city, and how to run it

City behaviour that should change between places lives in YAML: name, geographic and projected CRS, centroid, bounding box, boundary file, date window, baseline and recent year, grid resolution, buffer distances, pollutant list, the hotspot minimum, land-cover classes, the satellite collection, and the station list used by the seed. Delhi’s projected SRID is 32643. A city in another UTM zone changes that number in its own file. The analysis functions take the SRID from the loaded city.

To add a city: write config/cities/<slug>.yaml, provide a boundary, seed or ingest observations, and select the slug in the filter. Routes that are hard-wired to Delhi, including the built-up and AQI contours, return 404 for any other slug. That is deliberate. Those products name Delhi files.

16. Limits that belong in any explanation

These are properties of the study, not gaps to apologise for. They are why the maps are labeled the way they are.

  • The built-up gap is an observed association. Traffic, industry, and the choice of monitor sites come with built-up land and are not partialled out. Meteorology, season, topography, and population are named confounders and are not in the default regression.
  • The city mean can fall while the local built-up penalty stays. Emission controls, fuels, weather, and the 2020 lockdown are the things the caveat names for that citywide movement. The rebound after the lockdown is evidence about activity, not about land cover.
  • The surface between monitors is interpolated. Small patches are estimates.
  • Dynamic World labels shift from year to year. The comparisons use terciles and the multi-year pattern so that one wobbly year is not the result.
  • 2025–2026 AQI is a different index from 2018–2024. Quote them as a break in the series.
  • 2026 ends on 31 October.
  • OpenStreetMap industry and parks are incomplete. The database stores that sentence on industrial rows.
  • WorldCover year-to-year change can mix a new algorithm with a real change on the ground.
  • The seed’s monthly values, sketched roads, and tiny rasters are for booting the software.
  • There is no authentication, no weather covariate pipeline wired through the interface, and no live CPCB client. Those are listed as future work in the setup guide, alongside a validated land-cover classifier and vector tiles if a larger city outgrows GeoJSON.
A closing formulation

The platform stores observations in PostGIS, measures distance and area in UTM, and labels every derived layer. For Delhi, from 2018 onward, monitors with more Dynamic World built-up land within 1 km have worse annual AQI in the years that clear the data rules, while the city mean over those years is a separate series. That is the sentence the infrastructure was built to support, and to keep from being said more strongly than the data allows.
